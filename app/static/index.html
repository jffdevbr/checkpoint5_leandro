Achado que sustenta o trabalho: target leakage confirmado

Verificado nos dados, não assumido.

Energy_Intensity = (3,6 · Electricity_MWh + 0,035 · Natural_Gas_m3h) / Product_Yield_Tons com R² = 1,000000.

As colunas de consumo não são features — são o próprio target reescrito. Um modelo que as usa acerta quase 100 % e é inútil para otimizar: para prever a energia de uma configuração nova, seria preciso já saber quanta energia ela consumiu. Por isso Electricity_MWh, Natural_Gas_m3h e Steam_Tons_h ficam fora do pipeline.
  • Leakage secundário: Product_Yield_Tons é o denominador do target de energia — usá-lo como feature cria dependência circular entre os dois modelos dentro do otimizador.

Segundo achado: a alavanca real não é o setpoint

Também verificado nos dados.

Product_Yield_Tons = 0,18 · Feedstock_Flow_m3h · Sensor_Health_Index com R² = 1,000000.

Reactor Temperature, Reactor Pressure e Valve Opening têm correlação ≈ 0 com os dois targets — e continuam ≈ 0 dentro de cada unidade, então não é paradoxo de Simpson. A única variável operacional com efeito é a vazão de carga; e Sensor_Health_Index multiplica a produção diretamente.
  • Consequência: a condição do equipamento domina o resultado. Recuperá-la via manutenção vale mais do que qualquer ajuste de setpoint — é isso que torna a Pergunta 2 a decisão central.
  • Consequência: o ótimo é degenerado — temperatura, pressão e válvula são indiferentes dentro da faixa. Apresentá-los como “recomendação” seria falso; o critério de desempate usado é a menor perturbação em relação à operação atual.
  • Ressalva honesta: o dataset é sintético. Numa planta real esses setpoints teriam efeito — a ausência aqui é limitação dos dados, não conclusão de engenharia.
